APPLYING
--------
Extract ON TOP of your existing stonewater-price-app folder and let it
overwrite. Do NOT delete the folder first.

  unzip -o rga-price-app-v2.5.0.zip -d /path/to/PARENT-of-stonewater-price-app

Note "PARENT". Extracting inside the repo folder gives you a nested
stonewater-price-app/stonewater-price-app/ and nothing takes effect.

Then:

  npm test          # 53 + 57 assertions, 2 test files, 0 failed
  git add -A
  git commit -m "v2.5.0 scaffolding - expression parser, tests, PRD"
  # do NOT push yet if you want the release to land as one deploy

`git status` should show new files plus modifications to exactly six:
site/app.js, site/index.html, site/sw.js, site/styles.css, package.json and
CHANGELOG.md. site/prices.json must NOT appear. Anything else means something
from an earlier zip was never committed. Check before pushing.


CHECK THESE FOUR THINGS ON THE PHONE
------------------------------------
1. Type a plain number into Your price. It must behave exactly as in 2.4.1.
   This is the path used on every line and the one this release put at risk.
2. Type 30195*0.9, tap the x key on the strip mid-expression, then tap away.
   The strip must not vanish when you tap it, and the result must be 27176.
3. Tap the resolved field again. It gives back 30195*0.9, not 27176.
4. With two lines in the quote, focus the price field on the first. The second
   card must not move. Verified at 390px in the build, worth confirming on
   your own device.


ONE DIVERGENCE FROM THE MOCKUPS, ON PURPOSE
-------------------------------------------
The mockups showed the field holding a formatted value at rest. The real field
has always held a bare number, and formatting it would change the plain-number
path on every line - the exact path this release was most at risk of breaking.
So it still shows 27176, not ₹27,176. Changing that is a one-line edit if you
want it, but it should be a deliberate decision, not a side effect.


WHAT CHANGED IN BEHAVIOUR
-------------------------
Typing 30195*0.9 into Your price and tapping away gives 27,176, with a small
fx 30195*0.9 line underneath. Tapping the field again brings the expression
back, not the number.

Prices resolve to whole rupees, rounded half away from zero. The rounded figure
is the price and every total reads it. One consequence, accepted during scoping
and recorded so it is not raised later: 500000/12 gives 41,667, and twelve of
those is 500,004, not 500,000.

Plain numbers behave exactly as they did in 2.4.1. That path is the one to
re-test hardest after wiring, because it is used on every line and this release
changes the field it lives in.
